# adw-hybrid

Native Claude Code variant of the ADW cycle. Claude keeps `/adw`, Planner,
Gate, Verdict, and Engineer Review; only the Builder step uses the
local → Codex cloud → Claude ladder.

## Status

The canonical integration lives in `.claude/`: project skill, agents, rules,
hooks, and settings. The executor is encapsulated as helper scripts of the
`/adw` skill under `.claude/skills/adw/scripts/`; there is no parallel
entrypoint. The whole machine layer is English (user decision 2026-08-20).

Structure follows the official Claude Code docs for
[project skills](https://code.claude.com/docs/en/slash-commands),
[subagents](https://code.claude.com/docs/en/sub-agents),
[hooks](https://code.claude.com/docs/en/hooks-guide), and
[settings](https://code.claude.com/docs/en/settings). Standalone `.claude/`
configuration was chosen per Anthropic's recommendation for project-specific
customization; a plugin remains reserved for future distribution.

## Requirements

- Codex CLI with `codex exec` and `--json`.
- Local tier (mandatory by default):
  - Ollama running with the model tag in `ADW_LOCAL_MODEL`
    (current: `gpt-oss-64k:latest` — a `num_ctx 65536` alias of gpt-oss:20b;
    the Ollama 4096 default truncates Codex's tool definitions).
  - The `ollama-launch` Codex profile, generated by `ollama launch codex`
    (`~/.codex/ollama-launch.config.toml`: `wire_api = "responses"` + model
    catalog). Plain `codex exec --oss` breaks gpt-oss tool calling — never
    use it (verified 2026-08-20).
- Python 3, Git, `timeout`, `curl`.

## Escalation policy (user decision 2026-08-20)

No silent tier skipping. The local tier is required: missing model or failed
preflight stops the run with exit `2` (fix the infrastructure;
`ADW_SKIP_LOCAL=1` only as an explicit engineer decision). Escalation to
Codex cloud happens only after a genuine failed local attempt. If cloud also
fails (exit `20`), the orchestrator stops and presents the evidence —
`builder-claude` runs only with explicit engineer approval for that phase.

## Usage

```bash
cd adw-hybrid
claude
# Inside Claude Code:
/adw <task>
```

The session root must be this folder (or a project this `.claude/` was copied
into): settings, agents, and hooks only load from the session root.

The skill creates the plan and the gate with native Claude agents. Before
building, it materializes `adw/dispatch/phase-N.md` and `phase-N.files`,
seals gate + dispatch in Git, and calls the adapter. The adapter runs local
(one retry with gate output), then escalates as described above.

Plans with independent phases may run as a bounded wave. `/adw` verifies both
explicit dependencies and disjoint file ownership, creates one Git worktree per
phase, keeps local GPU inference serial, permits up to two cloud escalations in
parallel, and integrates verified commits one at a time with a gate after every
merge. Plans without independent phases retain the serial path.

Wave state is durable under `adw/waves/`. The manifest records the GPU snapshot,
latest dynamic grants, phase branches/worktrees, engine status, verdict,
verified commit, integration status, and loop-back count. The default local
grant requires complete GPU/Ollama telemetry, no CPU/mixed offload, and either
an already loaded GPU model or at least 12 GB free VRAM (override with
`ADW_LOCAL_MIN_FREE_VRAM_MB`).

Each attempt keeps stream, stderr, final message, gate result, and one JSONL
metric under `.claude/adw-runs/builders/`.

## Verification without models

```bash
bash .claude/skills/adw/scripts/run-e2e.sh
```

The harness uses temporary repositories and fake executables. It checks cloud
PASS with metrics, mandatory-local stop on failed preflight (exit 2), complete
cloud evidence, worktree reset, a two-phase wave with serial local attempts and
parallel cloud escalation, and deterministic serial integration. No network or
inference is used.
